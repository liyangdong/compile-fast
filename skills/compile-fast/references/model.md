# Explicit model contract

Install using the engine repository's `python scripts/install_skill.py`; it copies the current Python engine into this skill. Run through `python <skill-dir>/scripts/run.py`. A pip-installed `compile-fast` command is an optional alternative.

`compile-fast init --project <root> --release 17` creates an incomplete template. For a verified plain source tree without generators or annotation processors, pass its exact `--source-root` and repeat `--classpath` for every dependency. Use `--confirm-context` only when that context is known complete. The flag asserts completeness; it cannot discover it.

For multiple modules, edit `modules` in the model:

```json
{
  "schemaVersion": 1,
  "contextComplete": true,
  "buildFingerprint": {},
  "modules": [
    {
      "id": "core",
      "sourceRoots": ["core/src/main/java"],
      "dependencies": [],
      "classpath": [],
      "release": "17",
      "encoding": "UTF-8",
      "annotationProcessing": false
    },
    {
      "id": "app",
      "sourceRoots": ["app/src/main/java"],
      "dependencies": ["core"],
      "classpath": [],
      "release": "17",
      "encoding": "UTF-8",
      "annotationProcessing": false
    }
  ]
}
```

Keep the `buildFingerprint` generated by `init` / `resolve-maven`; `{}` is correct only when there are no build files. `dependencies` contains **all resolved reactor modules present on this module's compile classpath**, including transitives. `classpath` contains all resolved external compile/provided/system dependencies; preserve dependency mediation and exclusion semantics. Paths are relative to the target project unless absolute. Source roots must remain within the workspace and must not overlap. Do not include old reactor outputs or JARs on the external classpath; fresh outputs come from `dependencies`.

Supported options: `release`, or `source` plus `target`; `encoding`; `parameters` and `debug` booleans. Custom compiler arguments, JPMS and annotation processors currently require the normal build (L3). The engine verifies only modeled main source sets. Maven models use effective POM plus resolved compile classpath, and may require reactor artifacts already installed in the Maven local repository. Re-resolve after dependency/profile/settings/toolchain changes, including changes outside the workspace.
